### Known Issues
- **Known gap**: The character node ships dropdowns and a working API but no in-canvas preset manager UI, so preset changes require editing `character_presets.json` directly. `web/apex_preset_manager.js` is a reusable manager that nothing currently imports.

- HDRI/LoRA thumbnail rendering blocks async handlers
- Character prompt registration and inherited-store regression fixed September 20; standalone/API/package-registration validator passes. Live UI restart verification pending.
- **Preset black-and-white risk (audited and fixed September 24, 2026)**: the shipped libraries could force monochrome output, and the cause differed per node.
  - `prompt_presets.json` is runtime-authoritative and its Random pool is the JSON order, so a Random selection can inject literal monochrome wording: `Noir Detective Office` (Environment, "black and white noir atmosphere", 1.44% of that pool's weight), `Film Noir Shadow` + `Lightning Storm Flash` (Lighting, "stark black and white contrast" / "high contrast monochromatic moment", 4.33%), `Film Noir Classic` (Style, "high contrast black and white", 2.99%). Simulating `ApexPromptPreset.get_random_preset` over 200,000 seeds gives 8.51% of draws (1 in 12) with at least one enabled category on Random landing on monochrome wording; adding the silhouette/no-fill/chiaroscuro lighting presets plus the four other "noir" environment presets raises it to 19.0% (1 in 5.3). Reproducible seeds: Style 22/38/85/156/189/201, Lighting 34/127/140/184/193/197, Environment 94/139/190/201/274/291 (per-category seed offsets are +1/+2/+3).
  - `character_presets.json` never emits monochrome wording (0 of 221 presets; 0.00% over 200,000 all-Random seeds), but 42.02% of all-Random draws contain the word "silhouette" used as a shape word — hair Blunt Bob / Pixie Cut / Natural Afro / Mohawk Fade / Buzz Cut, headwear Fisherman Beanie, top Cropped Graphic Tee / Corset Top / Poncho Cape, bottom Leggings, shoes Chelsea Boots / Running Shoes / Oxford Shoes — which diffusion models frequently render as a literal dark figure against a bright background with high contrast.
  - Neither node adds a colour anchor or a monochrome negative, so nothing counteracts a monochrome cue once it enters the prompt. Apex Prompt also writes no negative text at all.
  - Secondary, dilution-only factor: combined prompts are long (character median 1,468 chars / min 1,303 / max 2,839; Apex Prompt full Random median 1,063 chars). `comfy/sd1_clip.py` tokenizes past 77 tokens into extra sections and `ClipTokenWeightEncoder.encode_token_weights` encodes every section rather than dropping it, so on CLIP-family encoders the later colour-carrying categories (eye colour, skin tone, hair, clothing) are diluted behind prompt-leading face-shape text instead of being silently truncated; encoders that honour only the first 77 tokens ignore them entirely.
  - Confirmation path when a monochrome render appears: read the Apex Prompt `style_text` / `lighting_text` / `environment_text` outputs (or the character `combined_prompt`) and check for the preset names above or for "silhouette".
  - **Root cause for the `Photorealistic` style (found September 24, 2026, and the likely trigger the user saw)**: the runtime text at `prompt_presets.json:1476-1479` is "Photorealistic, hyperrealistic, ultra-detailed, realistic textures, physically based rendering, ray-traced lighting, photorealistic rendering, film-quality realism, 8K resolution, ultra sharp focus, masterpiece, best quality." — it contains **no colour or palette word at all**. The Python default at `apex_prompt.py:474-475` still reads "…shot on 35mm film, soft natural light, realistic imperfections, **true-to-life colors**, ultra-detailed…", and it is the only preset where the shipped JSON lost a colour term the default still has, so the clause was dropped when the JSON library was expanded. Since the JSON entry wins at runtime (`apex_prompt_store.py:104-110`), picking Photorealistic gives the model a render/quality spec with zero chroma instruction: "photorealistic" then amplifies whatever the rest of the prompt implies, and with no colour cue the checkpoint's photographic prior resolves toward neutral/desaturated or full grayscale. Scale of the gap: 8 of 36 Style presets (22.6% of the Random weight — Photorealistic, Luxury Album Cover, Documentary Realism, Film Noir Classic, Art Deco Geometric, Gothic Dark Romance, Cottagecore Pastoral, Dieselpunk Industrial) and 21 of 50 Lighting presets (42.5% — Studio Professional, Silhouette Backlight, Ring Light Beauty, Dramatic Side Light, Film Noir Shadow, Bounce Light Soft, Butterfly Beauty Light, Split/Loop/Broad/Short Lighting, Clamshell Beauty, Hard Midday Sun, Overcast Soft Box, Spotlight Solo, Bounce Flash, Car Headlight Drama, Smoky Atmosphere, Window Frame Pattern, Contre-Jour Silhouette, Diffusion Filter Glow) carry no colour vocabulary either. The fix below restores "true-to-life colors" (plus a palette clause) in the JSON entry and mirrors it in `apex_prompt.py` so the two stay in sync.
  - **Fix applied September 24, 2026** (user chose the colour-anchor route): 29 `prompt_presets.json` entries — all 8 zero-colour Apex Style presets and all 21 zero-colour Apex Lighting presets — gained a colour/palette anchor. The two presets in that set that literally demanded monochrome were converted to colour-preserving noir wording: `Film Noir Classic` "high contrast black and white" → "high contrast noir lighting kept in rich color … full color noir palette", and `Film Noir Shadow` "stark black and white contrast" → "stark shadow contrast kept in rich color, warm amber highlights and cool teal shadows". The six of those presets that also exist in `apex_prompt.py`'s built-in defaults were mirrored there (6 lines) so a regenerated JSON cannot reintroduce the gap; the other 23 exist only in the JSON.
  - **Verified after the change**: JSON re-parses with unchanged category sizes (Environment 70 / Lighting 50 / Style 36 / Camera Lens 43), name order untouched, `apex_prompt.py` compiles, CRLF line endings preserved, a live `ApexPromptPreset()` instance returns the new text for every edited preset, and colour vocabulary now covers Style 0/36 and Lighting 0/50 with no colour word left. Diff scope is exactly 6 lines in `apex_prompt.py` and 29 lines in `prompt_presets.json`. Monochrome wording in a full Random draw fell from 8.51% to 3.54% (1 in 28); the silhouette/chiaroscuro/no-fill share is unchanged at 15.88%, so the combined "either" figure is still 19.07% because those lighting techniques were deliberately kept and only gained colour anchors.
  - **Deliberately not changed (outside the chosen scope)**: `Noir Detective Office` (Environment, "black and white noir atmosphere") and `Lightning Storm Flash` (Lighting, "high contrast monochromatic moment") still carry explicit monochrome wording and account for the remaining 3.54%; 18 of 70 Environment presets and 26 of 43 Camera Lens presets still have no colour vocabulary (they describe scenes and optics rather than a look); the character node's 13 "silhouette" shape words and the absence of a colour/negative output in either node are also untouched. The `Fashion Collage Portrait` name that the Python defaults add to Environment and Style is pre-existing behaviour, not part of this change.
  - Prompt user libraries are unaffected: only the factory JSON and the built-in defaults changed, so no user-preset migration is needed.
  - **Follow-up decision (open)**: with the new Apex Color slot, the 27 inline colour anchors added earlier are redundant and a pick such as `Monochrome Noir` can partly fight a style preset that says "rich natural color palette". Reverting those 27 anchors (keeping only the two Film Noir rewrites, which merely stop demanding monochrome) would make the colour slot authoritative. Not yet decided.
